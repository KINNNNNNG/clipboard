# Clipboard 0.1.2

本次发布为本地历史加上冗余与恢复能力：单个数据库文件损坏或误删，不再等于全部历史丢失，并新增从远端重建历史的入口。

## 为什么需要这次改动

历史数据库是本地记录的唯一起点。此前出现过一份 1548288 字节的库中有 367 页整页为零、SQLCipher 判定其不是数据库的情况，结果全部历史都无法读取，只能重建空库。0.1.2 引入经过校验的本地快照，把「单文件损坏等于全丢」变成「最多丢失最近一个快照周期」。

## 新增

### 本地快照冗余

- 客户端按累计 500 条写入、间隔到期（默认 30 分钟）或退出时创建快照，三者先到先触发。
- 快照覆盖全部本地记录：历史数据库、vault 标记、加密图片对象，以及收藏文件束缓存。
- 同一磁盘上优先使用硬链接，因此默认位置几乎不占额外空间；快照指向另一块磁盘时才真正复制。
- 默认保留最近 3 份，可在 1–10 之间调整；裁剪时同时清理不再被任何保留快照引用的对象与缓存文件。

### 启动自动恢复

- 历史数据库无法解密或已损坏时，客户端按时间从新到旧寻找第一个通过校验的快照并恢复，损坏的当前库会重命名为 `history.db.corrupt-<时间戳>` 保留下来。
- 只有在不存在可用快照时，才回退到「备份原库并重建空库」。

### 从远端恢复历史

- 设置页同步分区新增入口：确认后清空本地历史，客户端自动重启，并由启动同步从配置的远端拉取并合并历史。
- 该操作需要已启用并保存同步设置；原有本地数据库同样会备份保留。

## 校验与安全

- 创建快照前先用独立连接打开磁盘上的数据库并执行 `PRAGMA integrity_check`，通不过就跳过，不会把损坏内容当作备份。
- 快照写入后重新打开副本再次校验，并逐个比对对象的大小与 SHA-256；只有全部通过才写入清单文件，因此「存在清单」等于「已通过校验」，被篡改或缺失内容的快照会被自动跳过。
- 快照内容与主库同为加密数据，不引入明文；功能不新增任何凭据。
- 快照目录必须是绝对路径，且不得位于数据目录内部，避免快照与它要保护的数据一起被删除。

## 设置

- 快照目录：留空使用默认的 `%LOCALAPPDATA%\Clipboard\snapshots`，可填写另一块磁盘上的目录。
- 快照间隔：1–1440 分钟，默认 30。
- 保留快照份数：1–10，默认 3。

## 升级方式

从本页下载 `Clipboard-Setup-v0.1.2.exe` 覆盖安装即可，历史、密钥与设置都保留。安装前建议先校验哈希：

```powershell
Get-FileHash .\Clipboard-Setup-v0.1.2.exe -Algorithm SHA256
```

输出与 `SHA256SUMS.txt` 一致后再运行安装程序。

## 已知限制

- 允许丢失最近一个快照周期内的记录，不保证逐条零丢失。
- 快照目录必须可写；不可写时快照会被跳过并记录为失败，不影响剪贴板功能。
- 从远端恢复只覆盖进入同步的历史；文件束与文件内容仍只保留在本机，无法从远端恢复。
- 安装包尚未做代码签名，Windows SmartScreen 可能提示“未知发布者”。
