# Clipboard 0.1.1

本次发布修复了 0.1.0 安装包无法启动的阻塞缺陷，并首次提供客户端自动更新。

## 升级提示：0.1.0 用户必须手动覆盖安装

0.1.0 的安装包缺少 Windows 客户端的编译资源，安装后客户端在启动阶段就会崩溃退出，因此**无法通过自动更新完成升级**。请从本页下载 `Clipboard-Setup-v0.1.1.exe` 手动覆盖安装。

覆盖安装不会影响已有数据：剪贴板历史、vault 密钥、设置与同步凭据都保留在 `%LOCALAPPDATA%\Clipboard`，安装程序只替换程序文件。

## 下载与校验

本页提供两个文件：

- `Clipboard-Setup-v0.1.1.exe`：Windows 11 x64 自包含安装包
- `SHA256SUMS.txt`：安装包的 SHA-256 校验值

建议先校验再安装：

```powershell
Get-FileHash .\Clipboard-Setup-v0.1.1.exe -Algorithm SHA256
```

输出与 `SHA256SUMS.txt` 中的值一致后再运行安装程序。

## 修复

### 安装后无法启动（0.1.0 的阻塞缺陷）

- 现象：安装 0.1.0 后运行客户端，进程立即退出，退出码 `0xC000027B`，且不产生任何日志。
- 原因：`dotnet publish` 不会把构建阶段生成的 WinUI 编译资源（`Clipboard.Windows.pri` 与 `App.xbf`、`Views\*.xbf`）复制到发布目录。安装包封装的是发布目录，缺少这些资源的客户端在 XAML 初始化阶段抛出存储异常并崩溃。
- 修复：发布完成后显式补齐编译资源，并在打包流程中逐个校验；缺少任何一项都会直接终止打包，不会再产出同类坏包。

### 发布流程

- 修正发布流水线的产物路径。此前 artifact 保留了 `installer/` 子目录，导致 Release 只上传校验文件而缺少安装包 EXE。
- 修正 Windows 发布任务的 Inno Setup 安装方式。`windows-2022` runner 没有 `winget`，改用预装的 Chocolatey 安装；同时移除安装器对 `ChineseSimplified.isl` 的硬依赖。
- 移除 Windows 发布任务中不必要的 Windows App Runtime 安装步骤。客户端以 Windows App SDK 自包含模式发布，不依赖预装运行时。
- 修正工具链检查中的 Visual Studio 判定条件。原实现把 vswhere 查询限定为 `BuildTools` 产品，在只安装 Enterprise 或 Community 的机器上会中断验证。

## 新增

### 客户端自动更新

设置页新增“更新”区域：

- 显示当前版本，并可手动“检查更新”。
- 可开启“启动时自动检查更新”，默认关闭；开启后只在后台检查，不会自动下载。
- 发现新版本后可选择“下载并安装”或“跳过此版本”，跳过的版本会被记录，后续检查不再打扰。

更新过程只读取本仓库的 GitHub Releases，并且只接受形如 `Clipboard-Setup-vX.Y.Z.exe` 的安装器资产。下载完成后会依据发布的 `SHA256SUMS.txt` 校验 SHA-256，只有校验通过才允许安装。确认安装后客户端自行退出，由安装器关闭残留进程、替换文件并自动重启应用。

### 内核与接口

- Rust core 新增检查更新与下载安装包命令。
- 新增状态码 12–14，分别表示检查失败、下载失败与校验不匹配；既有状态码 0–11 保持不变。

## 变更

- 发布工作流合并为单一流程：在 Ubuntu 上校验 Rust 核心，在 Windows 上构建客户端与 EXE 安装器，两者都通过后才创建 GitHub Release。
- 客户端版本、安装器名称与 Release 产物统一由版本号驱动。
- 移除 `main` 分支推送与 Pull Request 的自动 CI 工作流。现在只有推送 `v*` Tag 或手动触发才运行 GitHub Actions，日常验证通过 `scripts/test-core.ps1` 与 `scripts/verify-windows-client.ps1` 本地执行。

## 安全

- 更新下载仅允许 `api.github.com`、`github.com` 与 GitHub 资产重定向域名，且必须是 HTTPS。
- 安装器资产名与版本号必须匹配，文件大小上限 200 MB。
- 校验不通过时会丢弃已下载的临时文件，且不提供安装操作。
- 更新功能不新增任何凭据，也不改变现有隐私边界：文件束、文件路径与文件内容仍然只保留在本机。

## 安装与卸载

- 按当前用户安装到 `%LOCALAPPDATA%\Programs\Clipboard`，不需要管理员权限。
- 创建开始菜单入口，并提供可选的桌面快捷方式。
- 卸载只删除程序文件，`%LOCALAPPDATA%\Clipboard` 下的历史、密钥、设置和日志都会保留。
- 应用以 Windows App SDK 自包含模式发布，目标机器无需预装 Windows App Runtime。

## 已知限制

- 安装包尚未做代码签名，Windows SmartScreen 可能提示“未知发布者”。
- 文件历史的跨设备同步尚未提供，文件束仍严格只保留在本机。
- 已签名的 MSIX 发布包尚未提供。
- 本地历史数据库损坏时会提示无法解密并保持应用可用，但暂未提供一键恢复入口。
