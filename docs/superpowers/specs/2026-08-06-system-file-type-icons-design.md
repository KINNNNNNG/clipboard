# Windows 系统文件类型图标设计

## 目标

让文件历史卡片使用与 Windows 资源管理器文件关联一致的系统图标，同时保持 `Win+V` 面板的即时弹出、搜索滚动流畅度和文件路径隐私边界。

本阶段只实现文件类型关联图标：例如 `.docx`、`.pdf`、`.zip` 使用 Windows 当前注册的关联图标，文件夹使用系统文件夹图标。多文件束继续使用第一个代表条目的类型和扩展名。

## 范围边界

- 不读取真实文件内容。
- 不检查文件是否仍然存在。
- 不生成图片、视频或文档缩略图。
- 不解析 `.exe` 内嵌图标、`.lnk` 目标图标或自定义文件夹图标。
- 不向搜索响应增加完整路径。
- 不改变文件束 `local_only` 和不同步文件路径的规则。
- Shell 图标失败时保留现有 Fluent 通用文件/文件夹 glyph，不阻塞面板使用。

## 数据来源

现有搜索响应已经返回：

- `representative_name`：代表文件或文件夹名称。
- `representative_kind`：`file` 或 `directory`。

Windows 客户端先从 `representative_name` 取得叶子文件名，再提取规范化扩展名，例如 `.DOCX` 归一化为 `.docx`。只有文件名首字符之后出现的最后一个点才表示扩展名：`archive.tar.gz` 使用 `.gz`，`.gitignore`、`README` 和以点结尾的名称均视为无扩展名文件。文件夹使用固定 `directory` 键；无扩展名文件使用固定 `file` 键。因此不需要修改 Rust Core、数据库迁移或 C ABI，也不需要为列表逐项调用 `ReadFileBundleAsync`。

图标缓存键为：

```text
directory
file
file:.docx
file:.pdf
file:.zip
```

多文件束只生成一个代表键，不读取其余条目。

## Shell 图标获取

新增 Windows 平台服务 `ShellFileTypeIconProvider`，通过 `SHGetFileInfo` 获取系统关联图标。调用使用 `SHGFI_USEFILEATTRIBUTES`：

- 文件传入虚拟名称，例如 `placeholder.docx`，并指定普通文件属性。
- 文件夹传入虚拟目录名称，并指定目录属性。
- 系统按当前文件关联返回图标，但不会访问实际文件、网络共享或 OneDrive 占位内容。
- 使用 32 像素大图标作为源，WinUI 在固定图标区域内按 DPI 缩放。

Shell 返回的 `HICON` 必须在转换后调用 `DestroyIcon`。图标通过 32 位 DIB 和 `DrawIconEx` 转换为 BGRA 像素，再在 UI 线程创建 `SoftwareBitmapSource`。所有 GDI 句柄在 `finally` 中释放。

平台服务只返回与 XAML 无关的像素数据，避免后台线程创建 UI 对象，也便于单元测试。

## 异步加载与缓存

文件卡片先显示当前 Fluent glyph，占位区域尺寸保持 `42 x 42`。只有 `ListView` 已实现可见项容器并触发 `Loaded` 或 `DataContextChanged` 时才请求系统图标。

加载流程：

1. 从卡片 ViewModel 生成图标缓存键。
2. 命中 UI 线程 LRU 缓存时立即复用 `SoftwareBitmapSource`。
3. 未命中时在后台线程调用 Shell/GDI 服务。
4. 回到 UI 线程创建图像源并写入缓存。
5. 再次校验卡片的数据上下文和图标键，防止列表虚拟化后把旧图标写到新卡片。
6. 成功时显示系统图标；失败或请求已过期时继续显示 Fluent glyph。

缓存容量固定为 128 个图标类型，成功和失败条目使用同一容量限制。缓存按类型而不是历史条目 ID 保存，因此大量 `.docx` 记录只占一个缓存项。成功条目在 LRU 缓存驻留期间不重复调用 Shell，被淘汰后再次可见时允许重新获取；失败条目缓存 5 分钟，到期后允许重试。并发请求按缓存键合并，避免同一扩展名在首次显示时重复调用 Shell。

## UI 呈现

- 保留现有文件卡片布局、名称和“共 N 项”。
- 系统图标放在现有 `42 x 42` 固定区域中央，最大显示尺寸为 `32 x 32`。
- Fluent glyph 位于系统图标下层，系统图标尚未加载或失败时自动作为降级显示。
- 图标加载不得改变卡片高度、文本宽度、选中边框或键盘滚动位置。
- 文本、图片卡片和图片预览缓存保持不变。

## 性能目标

- 面板显示和搜索结果绑定不等待 Shell 图标。
- 不因图标加载访问本机文件、网络路径或云端内容。
- 同一扩展名在缓存驻留期间最多执行一次成功的 Shell 获取；失败结果缓存 5 分钟，避免连续重试。
- 缓存满 128 项后按 LRU 淘汰。
- 列表快速滚动时，过期请求不得覆盖复用后的卡片。
- 图标服务异常不得导致面板关闭、搜索失败或粘贴失败。

## 错误处理

- Shell 返回失败、空图标或 GDI 转换失败：返回无图标结果并保留 Fluent glyph。
- 取消或卡片复用：丢弃结果，不显示错误提示。
- `HICON`、DC、DIB 等原生资源始终释放。
- 不记录代表文件路径，因为该实现根本不接收路径；诊断只允许记录图标缓存键和 HRESULT。

## 测试

- 缓存键测试：扩展名大小写归一化、文件夹、无扩展名、多点文件名和隐藏文件。
- 提供器测试：传给 Shell 的是虚拟名称和属性，不是真实路径；成功、失败和异常均释放原生句柄。
- 缓存测试：同一扩展名只加载一次、不同扩展名独立、容量淘汰正确、失败不会高频重试。
- 虚拟化测试：数据上下文变化后旧请求不能覆盖新卡片。
- XAML 契约测试：固定图标尺寸、系统图标绑定和 Fluent glyph 降级同时存在。
- Windows 全量测试、x64 构建和现有验证脚本必须通过。
- 手工验收 `.docx`、`.pdf`、`.zip`、普通文件夹和无扩展名文件；检查 100%、150%、200% DPI，并确认快速滚动无明显卡顿。

## 后续扩展

如果后续确认必须让 `.exe`、`.lnk` 或自定义文件夹与资源管理器逐项完全一致，可在独立阶段增加真实路径图标提供器。该阶段必须采用可见项惰性加载、后台线程、超时和路径级缓存，不能复用本阶段的无路径性能承诺。
