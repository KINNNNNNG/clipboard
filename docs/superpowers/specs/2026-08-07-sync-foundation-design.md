# 同步协议与设备配对基础设计

> **历史范围说明：** 本文描述的是阶段四的基础批次。其“真实 WebDAV/OSS、图片对象传输、WinUI 设置页、DPAPI 凭据和后台重试不在范围”已被后续实现计划扩展，不能被解读为当前缺口。真实服务和两设备验收仍属于阶段五，当前证据见 [Clipboard 开发状态](../../STATUS.md)。

## 目标

建立阶段 4 的第一个可验证纵向能力：两个本地 Core 实例通过目录型模拟远端交换端到端加密的文本同步事件。该能力同时提供恢复码、协议版本检查、确定性合并、文件束拒绝同步和脱敏诊断日志。

真实 WebDAV/OSS、图片对象传输、WinUI 设置页、DPAPI 凭据和后台重试不属于本次范围。

## 架构

新增独立的 `clipboard-sync` Rust crate，避免把同步协议、文件 I/O 和 Core 服务编排混入现有 crate。它只依赖领域模型、加密基元和存储抽象；Windows 客户端后续继续通过版本化 JSON FFI 调用 Core 命令，不直接处理同步密文。

```text
CoreService -> SyncService -> SyncTransport (DirectoryTransport for this task)
                  |                 |
                  |                 +-> vault/journal/{device_hash}/{segment}.enc
                  +-> SyncDiagnostics (desensitized events only)
```

每个设备只向自己的日志目录追加段。同步执行固定为拉取、认证解密、合并、再上传本设备待发布事件；无共享可写日志，也不依赖跨设备锁。

## 协议与加密

- 协议版本固定为 `1`，未知更高版本拒绝处理且不写入远端。
- 同步空间沿用 vault ID，设备 ID 是本地生成的 UUID。
- 每个日志段是一个独立 XChaCha20-Poly1305 对象，使用 `KeyPurpose::Journal` 的 scoped 子密钥。
- 日志段 AAD 包含协议版本、vault ID、设备 ID、段编号和对象类型；交换、篡改或错误 vault 的密文必须认证失败。
- 远端只保存公开协议头和密文段。协议头不含设备显示名、内容、恢复码或凭据。
- 本次仅同步文本记录、收藏状态和删除墓碑。图片会保留现有本地语义，但不生成同步事件，直到图片对象协议单独完成。

## 事件与合并

`SyncEvent` 采用稳定的版本化序列化，包含事件 ID、发出设备 ID、HLC、事件类型和必要的文本记录状态。入站事件先验证版本和 AEAD，再交给既有领域合并规则处理。

入口采取拒绝式边界：任意 `FileBundle` 或 `SyncScope::LocalOnly` 记录均返回 `LocalOnlyRejected`，不生成日志段、不调用 transport，诊断中也不包含文件名或路径。重复拉取相同段必须幂等；不同设备日志以任意顺序拉取都产生相同记录状态。

## 恢复码

恢复码编码 vault ID、32 字节主密钥、协议版本和校验码。它使用固定分组文本，解码时校验长度、版本和 checksum；任意字符篡改、截断或未知版本均被拒绝。恢复码不上传、不进入诊断日志，也不包含远端配置或凭据。

本次提供纯 Rust 编码/解码 API。Windows 的 DPAPI 保护、导入导出交互和配对文件密码将在后续任务实现。

## 目录型模拟远端

`DirectoryTransport` 用临时目录实现最小远端语义：列出设备目录和已完成段、原子写入新段、读取完整段。上传先写同目录唯一 `.pending` 文件并 flush，再原子 rename；读取端忽略 `.pending`。任何文件系统失败映射为不含路径的结构化同步错误。

目录布局：

```text
vault/
  header.json
  journal/
    {device_id_hash}/
      {segment_id}.enc
```

测试只能检查密文的存在和长度，不能在日志、错误或诊断中断言真实文本内容。

## 诊断日志

`SyncDiagnostics` 是注入式接口，默认 `NoopSyncDiagnostics`。实现记录下列结构化字段：

- 阶段：`pull`、`decrypt`、`merge`、`upload`、`reject_local_only`。
- 结果：成功或错误类别（认证、版本、I/O、格式、local-only）。
- vault、设备和段编号的单向短哈希。
- 段数、密文长度、耗时和重试序号。

不得记录任何文本正文、图片字节、文件名、路径、恢复码、主密钥、派生密钥、密码或凭据。单元和集成测试将把诊断写入内存，断言序列化记录不含敏感测试数据。

## 错误处理

- 网络和真实远端尚未接入；目录 I/O 失败返回 `Transport` 错误，不影响 Core 本地历史。
- 认证失败、格式无效和版本过新不合并任何该段事件，并记录脱敏诊断。
- 成功拉取的其他设备段仍可合并；失败段不会阻断本设备随后可上传的独立日志段。
- 同步入口不会自动创建后台线程。后续 Windows 调度层负责重试、退避和 UI 状态。

## 验收与测试

1. 两个临时 Core/Sync 实例离线写入不同文本，先后同步后均得到相同文本集合。
2. 同一段重复同步、反向拉取顺序和重复上传不改变最终状态。
3. 使用错误密钥、篡改密文或未知协议版本时，远端事件不会进入历史。
4. 文件束与 `local_only` 记录被同步入口拒绝；远端目录、outbox 和诊断文本不含文件路径或文件名。
5. 恢复码可往返；篡改、截断、错误校验和未知版本失败。
6. `.pending` 上传文件不会被读取为完成段，原子 rename 后才可被另一实例读取。
