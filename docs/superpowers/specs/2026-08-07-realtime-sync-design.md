# 实时同步设计

## 目标

在已启用远程同步且本地产生可同步数据变更后，自动发起远程同步。同步使用三秒合并窗口和十五秒最小自动同步间隔，以避免连续剪贴板捕获造成并发请求、重复上传或高频远端请求。

## 范围

- 文本和图片捕获成功后触发自动同步。
- 文件包始终仅保留在本地，不触发远程同步。
- 已有的“立即同步”和“测试连接”保持可用。
- WebDAV 和 OSS 共用同一调度逻辑。

## 调度策略

1. 每个可同步捕获通知调度器一次。
2. 调度器重置三秒延迟；延迟期间的多次通知合并为一次同步。
3. 自动同步之间至少间隔十五秒；间隔内的通知保留为待同步状态。
4. 同步任务始终串行运行。
5. 同步运行期间收到新通知时，记录待补跑状态；当前同步结束后，若已满足最小间隔则立即补跑，否则等待剩余间隔。
6. 用户发起的“立即同步”不受自动同步最小间隔限制。
7. 同步设置被禁用时，取消未开始的延迟任务，并忽略后续通知。
8. 同步设置保存后，下一轮同步读取最新已保存配置与凭据。

## 组件与数据流

新增后台实时同步调度器，依赖核心客户端、设置存储、凭据存储和全局日志。捕获协调器通过观察者事件通知调度器，调度器自行构建远程配置并调用核心同步接口；不经过设置窗口或 UI 线程。

```
捕获成功 -> 捕获观察者 -> 实时同步调度器 -> 核心同步接口 -> 远端存储
                                      |                    |
                                      +---- 全局日志 <-----+
```

## 错误处理与日志

- 自动同步失败不得阻塞捕获流程或影响后续捕获。
- 每轮自动同步写入 `sync.realtime.start` 与 `sync.realtime.end` 日志。
- 日志仅包含提供商、结果、脱敏错误类别、允许的错误代码和固定的操作标识；不记录账号、凭据、远端路径或剪贴板内容。
- 发生错误后，后续捕获仍可触发新的同步。

## 测试

- 多次通知在三秒窗口内只运行一次同步。
- 自动同步在十五秒最小间隔内合并通知。
- 运行期间有新通知时，在满足最小间隔后补跑一次。
- 手动同步不受自动同步最小间隔限制。
- 禁用同步时不运行同步。
- 文件包通知不触发同步。
- 自动同步失败会记录脱敏日志且不阻断后续调度。
