# 跨设备原生剪贴板设计

- 日期：2026-07-31
- 状态：设计已确认，等待书面规格复核
- 第一版平台：Windows 11 x64
- 后续平台：macOS

## 1. 产品目标

开发一个替代 Windows 11 原生 `Win+V` 历史面板的剪贴板应用。第一版支持文本、图片以及单个或多个文件和文件夹，窗口在当前鼠标光标附近打开，支持键盘优先的即时搜索和正则表达式搜索。用户选择记录后，应用立即把内容粘贴回原来的窗口。

多台 Windows 设备通过用户自己的 WebDAV 或 OSS 云存储同步文本和图片。文件记录、路径、元数据和文件内容完全保留在产生记录的设备上，不参与同步。云端只保存端到端加密的数据。项目从第一版开始使用可跨平台共享的 Rust 内核，后续为 macOS 开发 SwiftUI/AppKit 原生客户端，保持两端各自的系统风格。

## 2. 第一版范围

第一版交付以下能力：

1. 监听并保存 Unicode 纯文本、图片和 Windows 文件系统文件列表剪贴板内容。
2. 默认尝试接管 `Win+V`，失败时明确提示原因并允许用户设置备用快捷键。
3. 在鼠标光标附近打开 Windows 11 原生风格的 WinUI 3 面板。
4. 输入即搜索文本正文、文件名和本机文件路径，支持安全的正则表达式模式。
5. 图片可按复制时间、来源应用和内容类型筛选，不进行 OCR。
6. 方向键选择、`Enter` 立即粘贴、`Esc` 关闭。
7. 收藏记录，并保证收藏项不被自动清理。
8. 配置最大普通记录条数、普通记录保留天数、每台设备的图片缓存空间上限和收藏文件缓存空间上限。
9. 通过 WebDAV 或阿里云 OSS 同步文本和图片，云端数据端到端加密。
10. 多台 Windows 设备使用恢复码加入同一同步空间。
11. 系统托盘入口、同步状态、开机启动和设置页面。

第一版不包含：

- 富文本、HTML 和自定义剪贴板格式的保真粘贴。
- Outlook 附件等不提供真实文件系统路径的虚拟文件剪贴板格式。
- 图片 OCR 或以图搜图。
- Android、iOS 或浏览器客户端。
- 由产品方托管的账号系统或云端中转服务。
- 跨设备实时局域网直连。

文件记录的任何信息和内容都不参与同步。macOS 原生客户端属于后续路线，不纳入第一版验收。

## 3. 体验设计

### 3.1 面板外观

面板以 Windows 11 原生 `Win+V` 为基准做增强，不采用独立桌面软件式的重新设计。

- 顶栏只有剪贴板图标、`剪贴板` 标题、同步健康状态和 `全部清除` 按钮。
- 不显示表情、GIF、颜文字或符号 Tab，也不保留空 Tab 位。
- 顶栏下方直接显示搜索输入框。
- 搜索框右侧提供正则表达式 `.*` 开关和筛选菜单。筛选菜单包含时间范围、来源应用和内容类型。
- 历史记录继续使用原生白色卡片、更多菜单和固定图标。
- 卡片主区域显示内容，底部以次要文字显示来源应用、复制时间、来源设备和同步状态。
- 文本卡片展示多行摘要；图片卡片展示缩略图、像素尺寸和来源信息；文件卡片展示条目数量、代表性文件名、原路径或本机缓存状态。
- 面板跟随系统浅色、深色、高对比度和动画设置。
- 初始逻辑尺寸约为 386 x 500，有效高度不超过当前显示器工作区的 70%。列表使用虚拟化，不因记录数量增加而改变面板尺寸。

`全部清除` 遵循 Windows 原生固定项习惯，只删除未收藏记录。文本和图片删除产生同步墓碑，使其他设备最终得到相同结果；文件记录及其本机缓存只在当前设备删除。

### 3.2 调用和定位

默认快捷键为 `Win+V`。Windows 原生快捷键可能被系统保留，因此客户端使用低级键盘钩子尝试接管，并在首次启动时检测实际效果。

- 接管成功时，阻止原生历史面板出现并显示本应用。
- 接管失败时，说明需要关闭 Windows 自带剪贴板历史，或改用用户自定义快捷键。
- 备用快捷键通过标准全局热键注册，默认建议为 `Alt+V`，但不强制替换用户选择。
- 打开前记录原前台窗口句柄、鼠标位置、显示器 DPI 和工作区。
- 面板优先显示在光标右下方；空间不足时水平或垂直翻转，且不得越过工作区边界。
- 打开后搜索框获得键盘焦点，列表默认选中最近记录。

### 3.3 搜索和筛选

搜索针对文本正文、文件名和本机文件路径，不从图片提取文字。

- 保存原始文本，另建规范化搜索表示，搜索结果不得改变粘贴内容。
- 普通模式对文本正文、文件名和本机文件路径执行不区分大小写的即时子串搜索。
- 正则模式使用 Rust `regex` 类线性时间引擎，不允许回溯型表达式拖死界面。
- 无效正则在输入框内显示错误状态，并保留上一次有效结果。
- 文本、图片和文件都可按复制时间、来源应用、来源设备和内容类型筛选。
- 搜索和筛选在共享 Rust 内核中执行；文件记录只出现在产生它的本机结果中。

### 3.4 立即粘贴

用户单击卡片或按 `Enter` 后：

1. 内核读取完整内容。若图片只存在于云端，先下载并解密。文件记录优先使用仍然有效的原路径；原路径失效时，只能使用收藏时创建的本机缓存。
2. 收藏文件缓存以加密分块保存。粘贴前将其解密到带当前用户专用 ACL 的临时暂存目录。粘贴 60 分钟后开始清理；文件仍被接收应用占用时延后重试，并在下次启动时继续清理超过 24 小时且未被占用的残留目录。
3. Windows 客户端登记一次性抑制令牌，再把内容写回系统剪贴板。文件和文件夹使用 `CF_HDROP`，历史回放始终使用复制语义，不重放可能破坏源数据的剪切或移动语义。
4. 面板隐藏并尝试恢复打开面板前的前台窗口。
5. 仅在确认原窗口恢复成功后，通过 `SendInput` 发送 `Ctrl+V`。
6. 若原窗口不存在或无法恢复，不向其他窗口发送按键。内容仍保留在系统剪贴板中，并提示用户手动按 `Ctrl+V`。

应用写回系统剪贴板产生的变更由抑制令牌识别，不新增重复历史。

## 4. 总体架构

采用共享 Rust 内核加双原生客户端的结构。

### 4.1 共享 Rust 内核

Rust 内核不依赖 WinUI、AppKit 或具体操作系统 API，负责：

- 领域模型和记录状态。
- SQLite/SQLCipher 本地存储。
- 文本搜索和正则表达式。
- 内容判重和保留策略。
- 端到端加密、密钥派生和恢复码。
- 同步变更日志、冲突合并和重试队列。
- 本机文件清单、收藏文件加密缓存和临时暂存生命周期。
- WebDAV、阿里云 OSS 同步适配器。

建议的 Rust workspace 模块：

```text
core/domain
core/search
core/storage
core/crypto
core/sync
core/sync-webdav
core/sync-oss
core/ffi
```

### 4.2 Windows 原生客户端

Windows 客户端使用 .NET 8、C#、WinUI 3 和 Windows App SDK，负责：

- 原生面板、设置页、托盘菜单和系统主题适配。
- 剪贴板监听和格式读取。
- `CF_HDROP` 文件与文件夹列表读取，以及历史回放时的复制语义规范化。
- 全局快捷键、低级键盘钩子和冲突检测。
- 来源应用识别、窗口定位、焦点恢复和模拟粘贴。
- DPAPI 凭据和密钥保护。
- Windows 通知、开机启动和 MSIX 打包。

Windows 客户端通过稳定的 C ABI 调用 Rust 内核。FFI 只传递带版本的 DTO、错误码和事件，不把 WinUI 对象、Rust 所有权对象或数据库句柄跨边界暴露。

### 4.3 后续 macOS 客户端

macOS 客户端使用 SwiftUI 和必要的 AppKit 接口。它复用同一 Rust 内核、数据库模式、加密格式和同步协议，只重新实现：

- macOS 原生界面和材质。
- `NSPasteboard` 监听。
- macOS 全局快捷键。
- 菜单栏入口、弹窗定位和辅助功能权限。
- Keychain 密钥和凭据保护。

macOS 无需兼容 WinUI 布局，视觉和交互遵守 macOS 原生习惯。

## 5. 领域模型和本地存储

### 5.1 剪贴板记录

每条记录至少包含：

```text
id                  UUIDv7
vault_id            同步空间 ID
kind                text | image | file_bundle
content_fingerprint 带密钥的内容指纹
content_ref         文本密文、图片对象引用或本机文件清单引用
sync_scope          vault | local_only
source_app_id       来源应用稳定标识，无法识别时为 unknown
source_app_name     用于界面和筛选的显示名
source_device_id    来源设备
created_hlc         创建混合逻辑时间
last_used_hlc       最近复制或粘贴时间
favorite_state      收藏状态及其更新时间
delete_state        删除墓碑及其更新时间
byte_size           原始内容大小
sync_state          local_only | local | queued | synced | error
schema_version      记录格式版本
```

原始文本和搜索表示分开保存。图片统一编码为 PNG 后入库，避免依赖 Windows 特有的位图内存格式。来源应用识别是尽力而为能力，失败时记录为 `unknown`，不得阻止捕获。

文件记录的 `sync_scope` 固定为 `local_only`，并通过本机文件清单保存一个或多个顶层文件/文件夹的原路径、名称、类型、捕获时大小和修改时间。普通文件记录不复制实际内容；内容指纹只基于规范化路径和捕获时元数据计算，避免为了记录历史而读取大型文件。用户收藏记录时，客户端异步遍历并缓存文件实际内容，保留相对目录结构。原文件在收藏完成前已消失时，记录标记为不可用，不伪装成缓存成功。

### 5.2 本地数据

- SQLite 保存索引、状态和同步队列。
- SQLCipher 对数据库整体加密。
- 大图片和收藏文件内容以独立加密对象保存在应用私有目录，数据库只存引用和认证元数据。收藏文件使用适合流式处理的分块认证加密，不能为了加密把整个大文件读入内存。
- 首次启动即创建本地保险库和随机主密钥；数据库密钥由该主密钥派生，并由平台安全存储保护根入口。启用同步后，该保险库成为同步空间，无需重新加密本地历史。
- 日志不得记录剪贴板正文、图片内容、恢复码、访问密钥或密码。
- 第一版不发送第三方遥测。

## 6. 捕获和本地事务

Windows 客户端收到剪贴板变化后执行：

1. 读取 Unicode 文本、图片或 `CF_HDROP` 文件列表，同时尽力获取剪贴板所有者和前台应用。
2. 检查一次性抑制令牌，过滤应用自身为立即粘贴而写回的事件。
3. 对内容做大小检查、格式规范化和带密钥指纹计算。
4. 连续相同内容合并为一条记录，更新最近使用时间和来源信息。
5. 在同一逻辑事务中写入内容和元数据；只有文本和图片加入同步队列，文件记录强制保持 `local_only`。
6. 本地提交成功后才通知界面显示记录。
7. 后台执行保留策略和同步，不阻塞复制操作。

若剪贴板暂时被其他进程锁定，客户端使用短时、有上限的退避重试。最终失败只记录脱敏诊断信息，不清空现有历史。

## 7. 保留策略

保留规则分为同步空间全局规则和设备本地缓存规则。

### 7.1 全局规则

- 最大普通记录条数。
- 普通记录保留天数。
- 收藏记录不计入最大普通记录条数，也不受保留天数限制。
- 未启用同步时，全局规则只作用于本机；启用同步后，修改规则会生成加密设置事件并同步到其他设备。
- 由条数或天数清理的文本和图片生成墓碑，确保不会被其他设备重新下载；文件记录仅在本机删除，不生成同步事件。

默认值为 1000 条普通记录和 30 天，用户可关闭其中任一限制。

### 7.2 本地图片缓存规则

- 每台设备单独配置图片空间上限，默认 1 GiB，不跨设备同步。
- 达到上限时按最近最少使用顺序处理未收藏图片。已确认上传成功的图片只释放本地对象，保留记录并可在粘贴时按需下载。
- 未启用同步或尚未上传成功的图片不能只释放内容；此时删除最旧的未收藏图片记录，确保界面不会保留无法恢复的空记录。
- 仅释放已上传图片的本地对象时不生成墓碑；删除未上传图片记录时按普通删除处理。
- 收藏图片不被自动释放。收藏内容使实际占用超过上限时，设置页明确显示原因。

### 7.3 本地收藏文件缓存规则

- 文件记录默认只保存路径，不占用文件内容缓存。
- 用户收藏文件记录时，应用计算单个/多个文件或文件夹的总大小，并把实际内容按原目录结构加密缓存到本机。
- 文件夹遍历不跟随符号链接、目录联接或其他重解析点，避免越出用户选择范围或形成递归循环；界面列出被跳过的条目后再允许用户确认收藏结果。
- 每台设备单独配置收藏文件缓存空间上限，默认 5 GiB，不跨设备同步。
- 若新收藏需要的空间超过剩余额度，应用在开始复制前显示所需空间，并要求用户增大上限或取消；不得复制一半后把记录标记为已缓存。
- 收藏项永不自动清理，因此缓存上限是新缓存的准入限制，不会自动删除已有收藏文件。
- 用户取消收藏后，文件内容进入可清理状态；只有原路径仍有效时才可释放缓存而保留记录，否则需要明确提示释放后该记录将不可粘贴。
- 文件记录、原路径、文件名、目录结构、大小、缓存状态和实际内容都不得进入同步队列或云端对象。

## 8. 端到端加密与设备配对

### 8.1 密钥层级

- 首次启动生成随机 256 位本地保险库主密钥。首次启用同步时沿用该密钥并创建同步空间；加入现有空间的设备从恢复码导入对应主密钥。
- 使用 HKDF-SHA-256 和同步空间 ID 派生数据库、日志、图片、收藏文件缓存和内容指纹子密钥。
- 云端日志段和图片对象使用 XChaCha20-Poly1305 加密。
- 每个对象使用独立随机 nonce，并把同步空间 ID、对象 ID、对象类型和协议版本作为认证附加数据。
- Windows 使用当前用户范围的 DPAPI 保护主密钥和云存储凭据。
- macOS 后续使用 Keychain 保存相同用途的数据。

### 8.2 恢复码和配对文件

恢复码包含同步空间 ID、主密钥、协议版本和校验码，使用分组文本展示。恢复码不上传到云端，也不包含 WebDAV/OSS 密码。

应用还可导出配对文件：

- 文件包含恢复码信息、云存储类型和非敏感端点配置。
- 用户必须为导出文件设置一次性密码。
- 使用 Argon2id 从密码派生文件密钥，再使用 XChaCha20-Poly1305 加密文件内容。
- 访问密钥、密码和令牌不进入配对文件，新设备需单独填写。

丢失全部已配对设备和恢复码后，云端历史无法恢复。应用必须在启用同步时明确提示并要求用户确认已保存恢复码。

## 9. 云端同步协议

### 9.1 云端目录

```text
vault/header.json
journal/{device_id}/{segment_id}.enc
blobs/{object_id}.enc
snapshots/{snapshot_id}.enc
```

- `header.json` 只包含同步空间 ID、协议版本、加密套件和兼容性信息。
- 每台设备只追加自己的加密日志段，不共同覆盖同一日志文件。
- 图片先上传密文对象，成功后再提交引用它的日志事件。
- 每台设备在自己的日志中追加已处理版本向量。快照只覆盖所有活跃设备都已确认的事件；删除旧日志段前，必须确认所有活跃设备已经接受对应快照。
- 用户可把永久离线的设备标记为停用，使其不再阻塞日志压缩。停用仅影响同步维护，不会使已泄露给该设备的旧主密钥失效。

该结构避免依赖 WebDAV 或 OSS 的跨对象事务和全局文件锁。

### 9.2 同步行为

- 本地提交后把事件加入持久化队列。
- 同步入口按 `sync_scope` 做拒绝式校验，`file_bundle` 和 `local_only` 记录不得序列化为日志事件或远端对象。
- 联网时先拉取远端设备日志，再合并本地状态，最后上传本设备日志。
- 网络失败使用带抖动的指数退避，不影响本地复制、搜索或粘贴。
- 凭据失效时暂停自动重试并提示重新验证，避免持续锁定账号。
- 下载对象必须通过 AEAD 认证，认证失败的对象隔离为损坏数据，不进入历史。
- 图片可延迟下载，文本记录和元数据优先同步。
- 文件名、路径、文件清单、缓存状态和文件内容全部停留在本机；另一台设备不会看到对应记录的占位卡片。

### 9.3 冲突合并

- 事件使用混合逻辑时钟排序，设备 ID 作为完全相同时的稳定决胜值。
- 相同内容通过带密钥内容指纹判重，合并为一条记录并保留较新的最近使用时间。
- 收藏和取消收藏使用最后写入生效规则。
- 用户主动删除产生墓碑；墓碑优先于更早的收藏或使用状态。
- 只有已确认存在云端密文的本地图片缓存释放不是删除，也不产生墓碑。
- 合并函数必须满足确定性、幂等性和交换性，任意拉取顺序都得到相同结果。

云服务仍可观察密文对象数量、大小和访问时间。产品只承诺内容和敏感元数据保密，不宣称隐藏流量模式。

## 10. 错误处理

- 云服务不可用：保留本地能力，托盘显示非阻塞状态，后台重试。
- 图片未下载：卡片显示下载进度；下载完成前不执行错误或空白粘贴。
- 原窗口无法恢复：不发送按键，仅复制内容并提示手动粘贴。
- 无效正则：显示输入错误，不执行异常表达式。
- 本地数据库不可写：停止捕获新记录并明确通知，禁止伪装成保存成功。
- 文件原路径失效且没有完整收藏缓存：卡片标记为不可用，禁止写入空的 `CF_HDROP` 或执行粘贴。
- 收藏文件缓存空间不足、源文件读取失败或中途变化：终止缓存事务、清理未完成分块并显示失败原因，原路径记录仍可保留。
- 文件暂存失败：不写系统剪贴板、不发送 `Ctrl+V`，并清理已生成的临时内容。
- 密文认证失败：隔离对象、记录脱敏错误并继续处理其他事件。
- 同步协议版本过新：停止写入远端，但本地剪贴板继续工作，并提示升级客户端。
- `Win+V` 接管失败：保留应用可用性，引导关闭系统历史或设置备用快捷键。

任何错误都不得把剪贴板内容、密钥或云端凭据写入日志和通知正文。

## 11. 测试策略

### 11.1 Rust 内核

- 领域模型、内容判重和保留策略单元测试。
- 单个/多个文件和文件夹清单、路径规范化、收藏缓存准入、分块加密及失败回滚测试。
- 混合逻辑时钟与冲突合并的性质测试。
- 正则搜索、无效表达式和大文本性能测试。
- 加密已知答案、往返、错误密钥、nonce 唯一性和篡改拒绝测试。
- SQLite 事务失败、迁移、崩溃恢复和同步队列持久化测试。

### 11.2 同步适配器

- 使用本地 WebDAV 测试服务验证 PROPFIND、上传、下载、重试和并发日志。
- 使用本地 S3 兼容服务验证对象语义，并对阿里云 OSS 适配器运行同一契约测试。
- 覆盖断网、超时、限流、部分上传、损坏对象、凭据失效和远端对象丢失。
- 两个以上模拟设备以不同顺序交换事件，结果必须一致。

### 11.3 Windows 集成

- 文本、图片、单个/多个文件及文件夹捕获，来源应用尽力识别及自身写回防重复。
- 文件路径仍有效时回放、收藏后原文件删除时从缓存回放、无缓存失效状态，以及剪切记录始终按复制语义回放。
- `Win+V` 成功接管、系统冲突提示和备用快捷键。
- 光标定位、多显示器边缘翻转和每显示器 DPI。
- 原窗口恢复、`SendInput` 自动粘贴和失败降级。
- WinUI 浅色、深色、高对比度和键盘导航。

### 11.4 端到端验收

至少使用两台 Windows 11 x64 环境验证：

1. 双端分别复制文本和图片，联网后都能搜索和粘贴。
2. 双端离线执行复制、收藏和删除，恢复联网后最终状态一致。
3. 本机复制单个/多个文件及文件夹后可以搜索和粘贴；收藏完成后删除原文件，仍能从本机缓存恢复原目录结构。
4. 另一台设备看不到文件记录；云端对象中不存在文件名、路径、文件元数据或文件内容。
5. 云端文件中不存在可读文本、图片、来源应用、恢复码和访问凭据。
6. 云端完全离线时，本地复制、搜索和粘贴继续工作。
7. 在资源管理器、记事本、Edge、Office 和 VS Code 中人工验证快捷键与立即粘贴。
8. 覆盖 100%、150%、200% 缩放，多显示器和工作区边缘。

全局键盘钩子、前台窗口恢复和跨进程模拟粘贴必须保留人工系统验收，不能仅以自动化测试结果代替。

## 12. 发布与兼容性

- 第一版发布 Windows 11 x64 的签名 MSIX 安装包。
- 开发和自动化环境可生成未签名测试包，但不得把测试证书私钥提交仓库。
- 数据库和同步协议均带独立版本，升级必须提供向前迁移并拒绝不安全降级。
- Windows 客户端升级不得要求用户重新输入恢复码，除非本机安全存储已经丢失。

## 13. 主要风险与约束

1. `Win+V` 是 Windows 保留快捷键，部分系统策略或安全软件可能阻止钩子接管。备用快捷键是必要降级，不承诺所有环境都能无条件覆盖原生面板。
2. Windows 对前台窗口激活有限制。立即粘贴必须先确认原窗口恢复，宁可降级为已复制，也不能向错误窗口输入。
3. 部分应用延迟提供剪贴板格式或无法可靠识别来源。客户端采用有上限重试和 `unknown` 来源，不阻塞主流程。
4. WebDAV 服务实现差异较大。同步协议只依赖目录列举、读取、写入和删除等基础能力，并通过契约测试验证兼容性。
5. Rust 与 C# FFI 增加构建复杂度。FFI 必须保持窄接口、显式内存所有权和版本化错误模型。
6. 后续 macOS 仍需开发原生界面和系统适配层，但无需重写数据、加密、搜索和同步核心。
7. 大型文件夹的收藏缓存可能耗时并占用大量磁盘。缓存任务必须先计算规模、显示进度、支持取消，并使用事务式临时目录避免留下半成品。
8. 收藏文件粘贴需要短暂生成解密后的本机暂存文件。暂存目录必须限制为当前用户访问，并在宽限期、应用重启和异常恢复时清理；产品不能宣称收藏文件在粘贴过程中始终保持静态加密。
9. 第一版只支持提供真实文件系统路径的 `CF_HDROP`。Outlook 附件、浏览器虚拟下载等延迟渲染虚拟文件格式不在范围内。

## 14. 验收结论

设计完成的判断标准是：Windows 第一版能以接近原生 `Win+V` 的方式，在光标附近快速检索并立即粘贴文本、图片、单个或多个文件及文件夹；文件记录默认引用原路径，收藏后可从本机加密缓存恢复，并且任何文件信息都不跨设备同步；本地故障和云端故障均有安全降级；多台设备通过用户自有 WebDAV/OSS 获得文本和图片的端到端加密、最终一致历史；共享内核不依赖 Windows，能够被未来 macOS 原生客户端复用。
