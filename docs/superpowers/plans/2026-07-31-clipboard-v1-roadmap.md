# Clipboard V1 Implementation Roadmap

> **状态回填：** 截至 2026-08-25，阶段 1 至阶段 4 的工程交付已在 `codex/phase4-image-sync` 的 `2e4c3f6` 中落地；阶段 5 只完成发布验证基线和搜索性能子批次，不能宣称 V1 已发布。当前证据与未关闭验收见 [Clipboard 开发状态](../../STATUS.md)。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 分阶段交付 Windows 11 原生风格的本地剪贴板历史，并为文本和图片提供端到端加密的 WebDAV/OSS 跨设备同步。

**Architecture:** 产品由共享 Rust 内核、稳定 C ABI、Windows WinUI 3 原生客户端和可插拔远端存储适配器组成。文件历史严格保留在本机；文本和图片通过按设备追加的加密日志同步。每个阶段先形成可独立验证的纵向能力，再进入下一阶段。

**Tech Stack:** Rust 1.88、Cargo workspace、SQLite/SQLCipher、XChaCha20-Poly1305、.NET 8、C#、WinUI 3、Windows App SDK、Win32 API、WebDAV、阿里云 OSS、PowerShell 7。

---

## 为什么拆成五个计划

完整规格包含五个可以独立失败和验收的子系统。把它们放进一个计划会导致后续任务依赖尚未存在的接口，并且无法保持每个提交可运行。执行顺序固定如下：

1. 共享内核与 FFI 基座。
2. Windows 本地文本/图片剪贴板应用。
3. 本机文件与文件夹历史。
4. 端到端加密同步与设备配对。
5. 系统级验证、性能、安装包和发布加固。

上面的顺序是历史实施顺序。后续实际计划、代码和验收以本页修正后的链接及 [Clipboard 开发状态](../../STATUS.md) 为准；阶段五的真实环境工作不因阶段四的 fixture 通过而自动关闭。

## 阶段 1：共享内核与 FFI 基座

**详细计划：** `docs/superpowers/plans/2026-07-31-clipboard-core-foundation.md`

**交付结果：**

- 可重复构建的 Rust workspace 和 .NET FFI 冒烟程序。
- 文本、图片、文件束领域模型及 `local_only` 同步边界。
- 混合逻辑时钟和确定性状态合并。
- 主密钥派生、对象认证加密和 SQLCipher 本地存储。
- 文本/文件名/路径搜索、正则表达式和保留策略。
- 版本化 C ABI，可从 C# 打开保险库并执行命令。

**质量门：** `scripts/test-core.ps1` 全部通过，错误密钥不能打开数据库，`file_bundle` 无法进入 outbox，C# FFI 冒烟程序可以写入并搜索文本记录。

**当前状态：** 已验证实现。阶段完成检查中“当前工作区干净”只反映提交时刻，不是产品能力门。

## 阶段 2：Windows 本地文本/图片客户端

**计划文件：** `docs/superpowers/plans/2026-07-31-clipboard-windows-client.md`

该计划在阶段 1 完成后编写，覆盖：

- Visual Studio 2022 Build Tools、Windows 11 SDK 和 Windows App SDK 前置检查。
- WinUI 3 单一剪贴板顶栏、原生卡片、搜索、筛选和设置页。
- Windows 剪贴板文本/图片监听、PNG 规范化和来源应用尽力识别。
- `Win+V` 低级键盘钩子、备用全局快捷键、光标锚定和多显示器 DPI。
- 原窗口恢复、抑制令牌、系统剪贴板写回和安全 `SendInput` 粘贴。
- 系统托盘、开机启动、主题与高对比度适配。

**质量门：** 在记事本、Edge、Office 和 VS Code 中完成文本/图片捕获、搜索与立即粘贴；`Win+V` 失败时能降级到备用快捷键；不会生成自身写回的重复记录。

**当前状态：** 工程和自动验证已完成；可见 WinUI、DPI、多显示器和高对比度人工矩阵仍转入阶段五。

## 阶段 3：本机文件与文件夹历史

**计划文件：** `docs/superpowers/plans/2026-08-04-clipboard-local-files.md`

该计划在阶段 2 完成后编写，覆盖：

- `CF_HDROP` 单个/多个文件及文件夹清单捕获。
- 文件名与本机路径搜索，文件卡片状态。
- 默认仅引用原路径，历史回放始终使用复制语义。
- 收藏时扫描规模、拒绝重解析点、分块加密缓存和原子回滚。
- 原路径失效时从收藏缓存解密到受限暂存目录。
- 文件缓存上限、取消收藏和 60 分钟/24 小时暂存清理规则。
- 云端和同步 outbox 中不存在任何文件记录、名称、路径或内容的断言。

**质量门：** 原路径有效时可回放；收藏后删除原文件仍可恢复；未收藏且路径失效时明确禁用；另一设备和远端存储均看不到文件记录。

**当前状态：** 工程和 local-only 自动回归已完成；资源管理器真实回放与跨设备/远端负向验收仍转入阶段五。

## 跨阶段规则

- 严格执行 TDD：先写失败测试，再实现最小行为。
- 每个任务只提交其列出的文件，提交前运行对应局部测试和阶段测试。
- 不在 C# 中复制 Rust 的领域、搜索、保留、加密或同步规则。
- 不让 Rust 内核依赖 WinUI、HWND、DPAPI 或平台剪贴板类型。
- C ABI 只传固定宽度状态码、显式长度字节缓冲区和版本化 JSON DTO。
- 文件记录的 `sync_scope` 永远是 `local_only`；同步层执行拒绝式校验，而不是依赖调用者自律。
- 任何日志、异常、测试快照或 CI Artifact 都不得包含剪贴板正文、文件路径、恢复码、云存储凭据或主密钥。
- 真实 WebDAV/OSS 凭据只通过本机安全存储或 CI Secret 注入，不写入仓库。

只有五个阶段的质量门全部通过，第一版才可以宣称完成。阶段 1 完成不等同于应用可用；阶段 2 完成只代表本地文本/图片版本可用；阶段 3 完成才包含本机文件历史；阶段 4 的工程完成不等同于真实跨设备服务验收；阶段 5 完成后才能交付安装包。目前尚未达到这一条件。
